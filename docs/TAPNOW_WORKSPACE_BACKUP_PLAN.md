# TapNow 数据资产本地备份开发规划

修订日期：2026-09-08（Europe/Berlin）。状态：需求审阅稿；本次只修订规划，
不实现批量备份，不改变现有副驾驶。

## 1. 已确定需求

本轮最终目标是数据资产保管：把用户选择范围内、当前账号能看到的内容尽可能
忠实地保存到用户自己选择的目录，可验证、可恢复、可增量补漏。

| 决策 | 本轮要求 |
| --- | --- |
| 保存位置 | 用户明确选择目录，不默认散落到浏览器下载目录 |
| 范围 | 当前单画布、勾选画布、项目及子画布、选定工作空间、全部可见工作空间 |
| 权限 | 用户见到什么就备份什么，不按所有者或管理员角色过滤，不开发管理员功能，不绕过访问控制 |
| 内容 | 全部资源，包括未选中的备选、历史、输入、当前输出、附件和预览；不提供“仅当前产物”模式 |
| 原图失败 | 开发阶段查明根因并修复；生产阶段记录缺口、继续其他任务，后续增量补漏 |
| 云端消失 | 先尽力找回文件，不以 tombstone 代替恢复尝试，不删除本地已有资产 |
| 人工确认 | 用户可将验证过的内容加入可撤销的“无需下载名单”；不能自动加入 |
| learning | 本轮不实现学习、清洗、训练标签、数据集导入或第三方上传 |

“全部”指选定范围内所有可发现的资产和历史，不等于承诺找回从未被任何可访问
数据源记录、且云端和本地均已彻底丢失的字节。未知覆盖范围必须显式报告，不能
把“未发现”写成“不存在”。不重新生成图片冒充丢失原件。

## 3. 范围与用户流程

1. 从画布或扩展打开独立“备份中心”，不挤入节点审阅浮窗。
2. 选择当前画布（默认）、多个画布、项目树、一个或多个工作空间、全部可见范围。
   项目默认含子画布，单画布默认不自动扩展子画布；界面明确展示范围。
3. 选择本地目录，创建独立备份子目录；识别旧备份后可继续增量或新建。
4. 预扫描只读保存元数据和资源清单，显示已知数量、未知覆盖、预计字节及未知大小。
5. 确认开始，保存全部已发现资源；进度按成功、待处理、缺失、人工豁免分别计数。
6. 暂停/恢复、取消、按对象/原因重试、重新扫描、查看离线目录和完整性报告。
7. 增量补漏默认复查旧缺口，即使其父画布 `updated_at` 未变或已不在云端列表。

单画布中跨画布引用的资源属于该画布资产，尽量下载，保留外部来源占位信息；
不因此递归抓取无关画布全量内容。共享链接可打开但根列表未出现的画布允许从
当前页面或用户指定链接加入；不能只枚举 `team_shared` 就声称覆盖全部可见内容。
页面尚未保存但当前可见的内容作为独立 `runtime-observation` 保存，不覆盖云端
快照；来源不一致列入报告。范围扩大会合并旧索引，范围缩小不删除既有资产。

目录取消授权不开始写入；重启失去权限后请求重新授权。不同账号/工作空间 ID
隔离，禁止仅凭名称合并。目录搬迁后校验 `backup_id` 再续跑。云端名称和 URL
不能直接成为任意文件路径，使用稳定 ID、防路径穿越、预留名和符号链接逃逸检查。

## 4. 架构与交付形态

建议第一版为**纯 Chrome 扩展 + 独立备份标签页 + 用户目录**，保留未来本地
下载进程的适配边界，不把安装 companion 默认为用户已同意。

- 内容脚本负责当前账号上下文和经验证的 API 读取，不持久化登录凭据。
- 独立扩展页负责目录授权、控制和运行；后台只路由消息，不作为唯一长任务容器。
- 备份核心拆分枚举、发现、解析恢复、下载、存储、校验和状态，不依赖副驾驶/LLM。
- 任务日志持久化，关闭备份页或浏览器后可恢复；第一版不承诺关闭浏览器仍下载。
- 目录句柄只适用于相应浏览器上下文，不假设能传给未来本地进程作为路径。

Chrome 官方说明：扩展 service worker 可能终止；目录选择需要用户手势及授权。
因此不能用内存队列或 popup 承担可靠持久化。P0 必须验证真实扩展页上的目录选择、
写入、重新授权及生命周期，不能仅以普通网页演示替代。

官方依据（本次核对）：

```text
https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle
https://developer.chrome.com/docs/capabilities/web-apis/file-system-access
https://developer.chrome.com/docs/capabilities/browser-fs-access
```

如果大文件随机续写、请求头/CORS或生命周期实验不达标，再提出 companion
方案并明确安装成本；不得悄悄退回默认下载目录。companion 如启用，需额外设计
本机连接认证、目录选择、凭据短期交接、重定向/内网请求防护和安装包验收。

## 5. 数据格式与资产保管

```text
<用户目录>/tapnow-backup-<backup-id>/
  manifest.json
  objects/sha256/<prefix>/<sha256>.<ext>
  runs/<run-id>/
    scope.json
    workspaces/<workspace-id>/workspace.json
    canvases/<canvas-id>/
      canvas.json
      nodes.ndjson
      connections.ndjson
      history.ndjson
      references.ndjson
      relations.json
    assets.ndjson
    recovery-attempts.ndjson
    tombstones.ndjson
    report.json
    checksums.sha256
  state/
    checkpoint.json
    journal.ndjson
    partials/
  exceptions/
    no-download.ndjson
  catalog/
    index.html
```

- 全备份根目录内容寻址去重；跨画布相同字节只存一份，但所有引用与版本都保留。
- 每个 run 保存不可变快照；写入中状态与已提交状态区分，崩溃不能破坏旧快照。
- `scope.json` 记录明确范围、枚举覆盖和未证明的接口，不从成功数推断完整性。
- 原始对象使用 `{schema_version, source, raw}` 包装；原始未知字段保留，不向
  原始 payload 混入本地推导字段。凭据和签名查询参数例外，脱敏并记录字段路径。
- 引用身份包含账号域、画布/节点 ID、字段路径、历史/备选 ID、原始顺序及资源 ID；
  URL 不作为唯一身份，数组重排保留快照顺序，不把资源错认成新版本。
- 资产身份与引用、候选下载地址、实际内容哈希分开；一个逻辑资源可有原图和多个
  衍生文件，不能互相覆盖。未知原始性用 `unknown`，不能默认原图。
- 元数据包括 Content-Type、实际字节数、ETag、Last-Modified、尺寸/时长（可解析时）、
  SHA-256、原始性依据、文件路径、来源、发现时间、核对时间和恢复尝试索引。
- 临时签名 URL 仅运行时使用；持久化稳定 file ID、脱敏地址和刷新线索。备份不写
  token/Cookie/浏览器 profile，不将私人内容或可用签名 URL提交到仓库/公开日志。
- 最小离线目录能按画布/节点/历史找到文本和文件、显示缺口；HTML 转义所有远端
  文本，不执行下载的 HTML/SVG/脚本，不依赖云端图片。回写 TapNow 不在本轮。

## 6. 全资源发现

每种节点类型建立字段适配器，加递归结构扫描作为补充，不只读取 `src`：

- 当前输出、所有 `options` 备选（不按选中状态过滤）。
- 历史队列和元数据、任务结果、输入和跨节点引用。
- 图片、视频、音频、CSV、文档、其他附件及预览、封面。
- file ID、URL、数组、嵌套 JSON 和已知结构化文本字段。
- 当前页面 blob/data URL 或可读取缓存内容：保留来源；截图/Canvas 重编码只是
  衍生证据，不冒充原始字节。未知字段中疑似资源必须进入待分类清单。

先持久化每条发现记录，再排下载队列。不能把文本中任意网址当附件，也不能只按
文件后缀识别；按字段、响应类型和样本判断。第三方真实附件不得因当前域白名单
静默丢失，应按最小权限请求访问，用户未授权则标记待授权。凭据不转发到其他域。

完整历史单独记录覆盖：节点历史字段、页面历史列表、任务/附件接口是否均已核对。
只备份了当前节点 JSON 不足以宣布“历史完整”。没有接口证据则标记覆盖未知。

## 7. 原图失败与消失对象恢复

### 7.1 开发阻断门槛

每类真实失败建立案例：复现步骤、脱敏引用、file ID、实际请求上下文、响应类型、
状态码、页面是否能显示/下载、候选路径、根因、修复和回归测试。

**页面能下载原件而备份不能下载，属于阻断发布的缺陷。** 不能用 fallback、
豁免或“网络问题”关闭案例。真正服务端丢失也要有恢复路径检查记录，不能只有
一次 404。开发调试不执行生成/删除，不通过新生成伪造恢复。

### 7.2 恢复顺序

1. 先校验本地对象库及旧快照：已存在的原件直接复用；不依赖云端 URL 仍然有效。
2. 比较页面真实成功请求与下载器：file ID、Referer、Cookie必要性、响应 MIME、
   重定向、签名、CORS及实际生效请求头。不能假设在 fetch 写 Referer 就已生效。
3. 重读当前节点、所有备选/历史、画布详情、任务结果和附件元数据，查找同一对象
   的新地址。刷新地址只使用观察并验证的只读路径，不臆造接口。
4. 根据证据验证旧/新媒体域、原始下载端点、历史任务产物和其他已知引用。同 file ID
   或 URL 去掉 `small`/`tap_mx` 只是候选，不构成同内容或原图证明。
5. 在授权的当前浏览器上下文中检查已加载响应、Cache Storage/IndexedDB 的已知
   资源、blob 和页面原生下载行为；只读提取已有数据，不扫其他账号 profile，
   不清缓存或刷新页面导致唯一可用副本丢失。缓存不一定仍保有响应字节。
6. 对过期、429、5xx、超时和断流有限退避；每个来源独立记录证据和停止原因。
7. 原件仍失败时，保存所有可用衍生文件，保留原件缺口；已用尽可行来源才标记
   `unavailable-after-recovery`，并允许未来增量和人工验证。

恢复优先处理临时签名、blob、已消失对象等易失来源。预扫描不能丢掉已有响应
字节等易失证据；目录尚未授权时提示其风险并保持当前页面，不承诺事后找回。
生产恢复队列设置每对象尝试/时间预算和公平调度，不让单个死链接饿死其他下载。
预算耗尽是本次未解决，不是永久不存在的证明。

### 7.3 状态码不是根因

| 表现 | 开发排查 / 生产处理 |
| --- | --- |
| 401/403 | 分离登录过期、媒体防盗链、签名过期和真实无权；刷新合法上下文，不能盲重试 |
| 404/410 | 查身份、旧域、历史、任务产物、缓存和本地副本；不是立即跳过 |
| 200 但 HTML/JSON 错误 | 检测登录页/错误体、MIME和文件签名，不存作图片成功 |
| 429/5xx/超时 | 尊重 Retry-After、退避、降低并发，保留恢复点 |
| HEAD/Range 失败 | 尝试 GET；不能因 HEAD 不支持判定文件不可得 |
| 本地磁盘满/授权撤销 | 持久化后暂停受影响写入，不能不断失败耗尽任务或丢日志 |

## 8. 下载、增量与一致性

- 分页记录每页、游标、总数、ID集合，检测重复游标、重复页、空页仍有下一页。
  对列表 offset 分页的并发变更做去重和二次对账；根列表、子画布、节点、连线分别验证。
- 先保存快照和引用再下载；按域限流，初始低并发，配置更改不能隐式减少资源范围。
- 流式写临时文件，增量计算 SHA-256，不将大视频整体读入内存。
- Range 续传校验 206/Content-Range、偏移和对象验证器；返回 200 则重头覆盖临时
  文件，不能追加。ETag变化重启；416核对长度后才决定完整/重启，无可靠验证器则重下。
- 原件按收到的字节保存，不压缩。内容哈希证明本地一致性，不独自证明原始性；
  使用响应长度、文件签名、尺寸/时长及可用服务端校验信息交叉核对。
- 校验后再提交成功记录。原子 rename 能力必须按存储适配器实测；浏览器环境不能
  假设存在 POSIX rename，使用临时对象+提交日志，未提交对象不计成功。
- journal 先写、checkpoint可重建；同一根目录单写者锁；崩溃重启核对临时文件、
  已落盘对象和未提交记录，不能只信内存或状态 JSON。
- 增量不只依赖 `updated_at`。重扫资源/历史，比较原始 JSON 哈希和资源身份；
  必须检查本地文件仍存在，损坏/缺失重新排队。另提供全量本地哈希校验。
- 扫描前后版本/计数变化时重读受影响范围，有限重试后标记 `changed-during-run`；
  不承诺平台未提供的事务一致快照。
- 列表消失单独记云端状态 `not-listed / inaccessible / confirmed-deleted`；
  全量枚举未完成时不能推断删除。tombstone 与本地保存状态正交，云端已删但原件
  本地验证通过，不应把它误报为资产缺失。永不因云端消失自动删本地历史。

## 9. 失败、名单与完成语义

分别记录：

- 执行状态：待处理、下载中、暂停、待重试、已结束。
- 保存状态：未保存、已验证、仅衍生文件、恢复后仍不可得、本地损坏。
- 云端状态、原始性判断、发现覆盖、人工豁免各自独立。

单资源失败记录后继续其他资源；单画布 API失败后继续其他画布。全局登录失效
暂停需要登录的请求，仍可校验本地或处理不依赖登录的资源；恢复登录后继续。
目录完全不可写属于任务暂停，不属于“资源失败不中断”的例外伪装。

“无需下载名单”默认按当前缺失资源/版本及引用范围生效：

- 用户明确确认已验证，保存理由、时间、对象版本、引用位置及可选证据。
- 支持查看、撤销、导出和强制重试；批量加入也必须展示选择项并确认。
- 不自动豁免整个节点未来的新产物，不以宽泛域名/URL前缀匹配。
- 新版本/file ID/内容变更不继承旧豁免；恢复发现新来源时提示可复核。
- 豁免抑制默认重试，不删除缺口和尝试记录，不计为已下载。

完成报告分两个维度：

| 维度 | 含义 |
| --- | --- |
| 任务已结束 | 本次队列处理结束，可以有缺口 |
| 完整备份 | 所选范围枚举、图、文字、全资源及历史覆盖均通过，无原件缺口 |
| 部分备份 | 有缺口/仅衍生/覆盖未知/不一致，逐项显示 |
| 已处理（含人工豁免） | 无待执行项，但仍清楚显示人工豁免数和未保存数 |
| 无可用快照 | 基础读取失败，仍保留诊断与可恢复状态 |

资源计数按唯一目标和引用数分别显示。未知总量不能显示虚假 100%；人工豁免
不提高物理文件完整率。离线目录和报告中都能找到失败引用及恢复操作。

## 10. 分阶段开发与门槛

### P0：证据、失败根因和存储可行性

交付：脱敏接口契约、原图失败案例表、全资源字段地图、目录/续传实验报告及固定
测试样本。先单画布，不做 UI 大规模铺设。

- 核对个人/共享/工作空间列表、子画布和历史实际请求，记录分页与可见性语义。
- 对原件成功、原件失败但页面可见、云端消失三类真实样本执行完整恢复链。
- 核对图片/视频/音频/附件、大文件及备选资源，未知类型明确列出。
- 验证纯扩展目录与实际请求头、CORS、流式写入/增量哈希、关闭恢复。

门槛：页面可下载而工具失败的已知缺陷已修复并回归；未解决项有证据，不用豁免
代替修复。存储方案不达标则先解决架构，不能把风险留到上线。

### P1：可验证的单画布全资产备份

交付：分页、所有历史/备选发现、恢复解析器、下载器、对象库、manifest、日志、
完整性核对、最小离线目录及自动化测试。

门槛：所有发现引用均有文件或明确缺口；没有数量/字节静默上限；断网/关页后
恢复；重复运行不重复实体；原件未被压缩。历史/备选从此阶段开始，不拖到后续选装。

### P2：范围选择、增量与人工闭环

交付：备份中心、单画布/项目/工作空间范围、目录选择、预扫描、队列控制、增量
补漏、云端消失恢复、无需下载名单及离线核验。

门槛：旧失败不因父对象未变化或消失而遗漏；人工豁免可撤销；单失败不阻塞其他
画布；多工作空间和跨画布引用归属正确。本轮最终验收必须包含此阶段。

### P3：发布验收

交付：真实数据回归报告、安装包、备份格式说明、故障恢复说明。
验收包含长任务、目录移动/撤权、浏览器重启、磁盘不足、账号切换和全量哈希核对。
不加入 learning、云存储、计划任务或新管理员功能扩大本轮范围。

建议写集（开工后创建，不是当前已实现）：

| 模块 | 责任 |
| --- | --- |
| `utils/backup/types.ts`、`schema.ts` | 状态、格式版本、身份与记录契约 |
| `utils/backup/enumerate.ts`、`discover.ts` | 分页、范围、全资源引用发现 |
| `utils/backup/resolve.ts`、`download.ts` | 恢复证据链、请求、续传 |
| `utils/backup/store.ts`、`reconcile.ts` | 对象库、提交/恢复、校验 |
| `utils/backup/sync.ts`、`exceptions.ts` | 增量、消失对象、人工名单 |
| `entrypoints/backup/` | 独立备份中心与目录授权 |
| `test/backup/` | 固定样本、模拟服务、崩溃与端到端测试 |

复用现有 WXT和测试体系，备份通路不调用 LLM、不引用审阅压缩/字符限制。
选择增量哈希等依赖前核查浏览器兼容、维护和许可证，用已有可靠实现而非自写密码算法。

## 11. 验收矩阵

| 场景 | 必须证明 |
| --- | --- |
| 单画布 | 不扩为全部工作空间；跨画布引用资源保存但不抓取无关图 |
| 项目/工作空间/共享链接 | 子画布与列表分页对账，不按管理员/owner排除可见对象 |
| 1,000+ 节点 | 服务端500条硬上限、重复/失效游标均无静默截断 |
| 当前/备选/历史/附件 | 每条引用进入清单并尝试保存，未知字段有风险项 |
| 重复和数组重排 | 内容去重，来源路径/顺序不丢、不串图 |
| 原件25 MB以上、大视频 | 不压缩、不整文件读内存，完整长度/哈希验证 |
| 页面成功而工具失败 | 查明根因修复，作为发布阻断项 |
| 失效URL但历史/缓存可得 | 恢复对应字节，记录来源/原始性，不提前跳过 |
| 原件真正不可得 | 全恢复路径有记录，保留衍生、任务继续、后续可补漏 |
| 401/403/404/429/5xx | 分类、预算、登录恢复和公平调度 |
| 200错误页/短读/损坏 | 不误判成功，重试后可验证 |
| Range返回200/206/416、ETag变化 | 不混拼不同版本、不重复追加 |
| 关页/重启/提交时崩溃 | 日志可重建，未提交文件不算成功 |
| 云端消失但本地已保存 | 本地不删除，tombstone不等于资产缺失 |
| 云端恢复/旧失败父图未变 | 增量重新发现并补齐 |
| 人工名单 | 不等同下载成功、可撤销、新版本不继承 |
| 磁盘满/目录撤权/并发运行 | 可恢复暂停、单写者，旧快照不损坏 |
| 枚举期间协作编辑 | 检测不一致，不宣称事务快照 |
| 离线打开/文件损坏 | 无云端依赖；可定位文本/文件/缺口并触发核验 |
| 安全回归 | 无凭据泄漏、路径穿越、任意远端脚本执行或新增LLM调用 |

单元测试覆盖固定数据与状态转换；模拟HTTP服务覆盖状态码/响应异常；真实扩展
端到端覆盖目录授权和生命周期。真实试验只用授权数据，失败和消失场景优先用
已有案例及模拟服务，不主动删除用户资产。没有真实样本的类型标记“待实测”，
不能以模拟通过声称已验证生产可下载。

## 12. 审阅与待补证据

核心需求已明确，可在审阅通过后进入 P0，不再询问是否备份历史、失败是否继续、
管理员或 learning。

本轮已确认采用：纯扩展独立备份页；关闭浏览器后下次恢复；项目含子画布；
单画布不含子画布；无需下载名单按具体资源版本/引用生效；本地已有资产永不自动删除。

或扩展生命周期中断后，任务必须保存检查点，用户下次打开备份中心时继续恢复。

入口、各媒体原件定位、过期链接刷新、可见失败样本和消失资源恢复结果、目录写入
与重启续传。缺少账号或样本时才请用户提供对应授权入口，不索要密码/token。
