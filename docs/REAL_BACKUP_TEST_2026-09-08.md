## 插件执行证据

1. 在有真实登录态的 VNC Chromium 中，原生目录选择器选取一个空的测试目录，
   确认 Chrome 写入权限。小规模写入后独立复核，再暂停和继续。
2. 继续任务 ID：`run-1788895277911`。该轮复用了先前暂停时已验证的 32 个目标。
   队列结束时间为 2026-09-08 20:06:10 UTC（柏林时间 22:06:10）。
3. 报告标记 `producer: chrome-extension`、`transport: extension-fetch`、
   `writer: FileSystemAccess`。这些标签之外，另有真实原生授权和网络观察证据。
4. 附加到扩展页的只读 CDP 观察器，在 30 秒内观察到 45 个媒体响应，
   其中 44 个是 206；43 个可匹配的请求附加头含主站 Referer，未观察到
   Authorization。观察器不发下载请求，也不写媒体文件。
5. `verify-backup.mjs` 独立读取磁盘实际文件并流式计算 SHA-256，
   1,792 个物理文件与全部 2,457 个成功目标的字节数、哈希均通过。
   它是校验器，不是下载器。

## 为什么还有 32 个目标没有保存

32 个都是 `currentSourceFileId` 字段引用的 file-ID-only 目标。按已验证的
存储路径解析并重试后仍返回 HTTP 404，保留为 `unavailable-after-recovery`。

该状态只表示**目前实现的来源尝试后仍未得到文件**，不证明云端已永久删除，
更不证明所有历史、任务和浏览器缓存恢复路径均已穷尽。不能用同节点另一个
可用 URL 的图片冒充这个旧 file ID 的原件。可用 URL、备选和历史资源已分别保存，
缺失目标继续保留，后续增量会重试。

本轮仍需完善失效对象的更广恢复来源和人工可撤销的“无需下载名单”。

## 预算和隐私

本台服务器按用户授权，真实测试总预算不超过测试开始时剩余磁盘约三分之一。
主样本基线和插件结果合计约 22.91 GB 去重媒体，另有元数据、日志和少量测试文件。
插件运行设置 20 GiB 新增预算；它不是对用户文件系统剩余空间的测量。

原始资产、账户内容、截图、校验清单、浏览器配置均留在 `artifacts/private/`，
不提交 GitHub。公开报告只发布汇总与代码。远程查看器没有内建登录，
只应在可信访问环境使用，外部团队部署应加认证代理或隧道。
