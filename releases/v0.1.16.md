# TapNow Backup v0.1.16

修复本地资产库打开关系画布时报错：

```text
Please provide an icons object.
```

## 原因

这是查看器的图标初始化错误，不是因为资产由 0.1.14 下载，也不是这个错误证明了备份损坏。
0.1.15 源码已有图标参数修复，但发布 ZIP 误用了修复前的产物。这是我们的发布流程疏漏。
本版从修复后的源码重新打包，保留原有备份格式，不需要为解决显示错误重新下载资产。

## 更新

仅更新备份扩展，副驾驶保持 0.1.15 即可。

1. 下载并解压 `tapnow-backup-0.1.16-chrome.zip`。
2. 在 `chrome://extensions` 更新原 Backup 扩展的文件并点击重新加载；若使用新目录，则停用旧 Backup 扩展，再加载新目录。不要同时启用两个 Backup 版本。
3. 确认显示版本 0.1.16，关闭旧的本地资产库标签页，重新打开“查看本地备份”。
4. 选择原备份目录；不删除或覆盖备份文件，不需要重新下载。

## 发布检查

`extension:zip` 现在自动将本轮新生成 ZIP 中的每个文件与构建目录逐字节比较，
检查版本后才复制到发布目录，避免手动复制旧包。

安装包级回归检查：

```bash
DISPLAY=:94 npm run extension:test-release -- \
  releases/tapnow-backup-0.1.16-chrome.zip \
  /path/to/real/tapnow-backup/canvas-id
```

需要 Linux 图形桌面、xdotool、Playwright Chromium。测试输入真实目录路径后，
测试人员在原生选择器中确认目录和读取授权，其余显示与哈希核对自动执行。
使用一份已完成的真实备份；结果及截图保存在忽略提交的 `artifacts/private/` 下。
