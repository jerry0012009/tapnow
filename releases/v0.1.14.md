# TapNow Companion 0.1.14

本版重点修复画布来源绑定、已打开页面连接、副驾驶入口可见性与全屏行为。

## 使用流程

1. 在 TapNow 打开具体画布，例如 `https://app.tapnow.ai/canvas/<canvas-id>`。
2. 点击右下方“备份此画布”。项目列表页只作为入口，不能直接作为备份对象。
3. 备份中心会显示画布名称、画布 ID、来源标签页和原画布链接；确认无误后扫描。
4. 选择本地目录并授权 Chrome 写入，点击“开始 / 增量补齐”。

扩展会尝试连接当前已登录的画布页面；页面已提前打开时会动态挂接桥接脚本，不要求刷新。画布切换或关闭会清空旧扫描结果，不会静默改备份目标。单项下载失败会记录并继续，后续可对同一目录增量补齐。

## 本版修复

- 新增动态桥接，处理已打开画布缺少内容脚本时的“Receiving end does not exist”。
- 修复 Chrome 消息监听器互相抢响应导致的空结果和“请求失败”。
- 具体 canvas URL 与来源标签页双重绑定，排除 `/canvas/projects`。
- 副驾驶和“备份此画布”入口固定在独立最高层，避免被 TapNow UI 覆盖；支持拖动、恢复位置和窄窗口。
- 全屏画布下入口保持可用。
- 备份页显示明确名称、ID、来源与标签页，不再按第一个标签页自动选择。
- 新增消息分发回归测试。

## 验收边界

- 本轮实测环境是服务器 Linux 上的 Chrome for Testing，不是 Windows 实机；此包仍为 Windows 试用预发布版。
- 备份中心仍是独立扩展标签页，但由当前画布入口打开并绑定来源；没有改为内嵌 iframe。
- 目前枚举已打开的具体画布，不支持自动枚举整个工作空间。
- 保持 Chrome 和备份页打开；关闭后不继续下载，下次可选择相同目录增量补齐。
- 新安装或更新后，刷新 TapNow 页面可加载新的页面入口；备份页的“重新连接”无需刷新原画布。
- 62 项自动测试和备份模块类型检查通过。扩大至旧副驾驶/LLM 模块的类型检查仍有既存错误（图片类型、设置及审阅结果类型），本版不宣称全扩展类型检查或 LLM 工作流验收通过。
